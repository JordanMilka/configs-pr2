# Сравнение со штатными инструментами apk

Требование этапа 5: сравнить результаты со штатными инструментами
визуализации менеджера пакетов и объяснить расхождения. У apk штатный
инструмент - команда `apk dot` (граф зависимостей в формате Graphviz).
Для прямых зависимостей сравнивается также `apk info -R`.

## Окружение

| Параметр | Значение |
|----------|----------|
| Alpine Linux | 3.20.10 (образ `alpine:3.20`) |
| apk | apk-tools 2.14.4 |
| Репозитории | `v3.20/main`, `v3.20/community` |
| Индекс | 24174 пакета |

Эталонные выводы сохранены в `tests/data/apk_tools/` (`dot_*.txt`,
`info_R_*.txt`, `environment.txt`). Граф `depgraph` строится по
выгрузке индекса `tests/data/alpine_v3.20_main_subset.txt`, снятой с того
же репозитория `main`; версии всех пакетов в обоих источниках совпадают.

Как получены эталоны (в контейнере Alpine):

```
apk update
apk dot curl
apk info -R curl
```

## Результаты

Сравнивались три пакета: `alsaconf` (глубина 3), `curl` (4),
`util-linux-dev` (5). Узлы и рёбра сравнивались по именам пакетов без
версий.

| Пакет | apk dot: узлы / рёбра | depgraph: узлы / рёбра | Результат |
|-------|-----------------------|------------------------|-----------|
| `alsaconf` | 20 / 46 (47 строк) | 16 / 33 | наш граф - часть графа apk dot |
| `curl` | 22 / 48 (50 строк) | 16 / 33 | наш граф - часть графа apk dot |
| `util-linux-dev` | 16 / 31 (31 строка) | 16 / 31 | полное совпадение |

Во всех трёх случаях каждое ребро `depgraph` есть в `apk dot`. Если из
графа `apk dot` убрать четыре пакета `dash`, `dash-binsh`, `yash`,
`yash-binsh` и всё, что достижимо только через них, множества рёбер
совпадают: 33 и 33, 33 и 33, 31 и 31. Прямые зависимости, которые
выводит `stage2`, совпадают с `apk info -R` построчно (2, 4 и 8 записей).

## Расхождения и их причины

**1. Несколько поставщиков `/bin/sh` (`alsaconf`, `curl`).**
Зависимость `bash` и `ca-certificates` от `/bin/sh` может быть
удовлетворена тремя пакетами: `busybox-binsh`, `dash-binsh`, `yash-binsh`.
`apk dot` рисует всех кандидатов и их собственные зависимости. Поэтому в
его графе появляются `dash`, `dash-binsh`, `yash`, `yash-binsh`, а у
`curl` ещё `libncursesw` и `ncurses-terminfo-base`: до них можно дойти
только через `yash`. `depgraph` строит граф одного разрешения зависимостей
и берёт первого поставщика в индексе (`busybox-binsh`), поэтому
альтернативных пакетов в нём нет. В `util-linux-dev` зависимостей с
несколькими поставщиками нет, графы совпадают целиком.

**2. Красные рёбра.** В выводе `apk dot` красным нарисованы 6 рёбер у
`alsaconf` и `curl` (у `util-linux-dev` их нет). Все они соединяют только
четыре альтернативных пакета из пункта 1. Мы фиксируем только
наблюдаемое: `depgraph` эти пакеты не выводит, поэтому красных рёбер нет.

**3. Повторяющиеся рёбра.** `apk dot` рисует отдельное ребро для каждой
зависимости: если пакет требует другой и по имени (`libcrypto3=3.3.7-r0`),
и по виртуальному имени (`so:libcrypto.so.3`), получается два ребра между
одними пакетами (47 строк против 46 уникальных пар у `alsaconf`,
50 против 48 у `curl`). `depgraph` объединяет их в одно ребро.

**4. Подписи рёбер.** `apk dot` подписывает ребро виртуальной зависимостью
(`so:libc.musl-x86_64.so.1`, `/bin/sh`, `pc:sqlite3`, `pkgconfig`) и
рисует стрелку `inv`; ребро без подписи - зависимость по имени пакета.
`depgraph` показывает только факт зависимости между пакетами, без подписи:
виртуальные имена в нём заменены пакетами-поставщиками.

**5. Версии и формат.** В именах узлов `apk dot` стоят версии
(`curl-8.14.1-r2`), в `depgraph` - только имена (версия корня задаётся в
конфигурации). `apk dot` описывает граф в формате Graphviz
(`rankdir=LR`), `depgraph` - в формате Mermaid и в виде ASCII-дерева. Уровни
BFS, циклы, фильтр по подстроке, обратные зависимости и тестовый режим
есть только у `depgraph`. `apk dot` всегда берёт последнюю версию пакета в
репозитории, `depgraph` - заданную.

## Что не проверено

Какого из трёх поставщиков `/bin/sh` выбирает решатель `apk` при
установке пакета, из вывода `apk dot` не видно: он показывает всех
кандидатов. Поэтому утверждение «`busybox-binsh` - выбор apk» здесь не
делается; сказано только, что `depgraph` берёт первого поставщика в
индексе, а он присутствует среди вариантов `apk dot`. Попытка получить
решение установщика командой `apk add --simulate` завершилась ошибкой
(не был создан каталог root), поэтому в сравнение она не вошла.

## Как воспроизвести

```
python -m unittest discover -s tests -p "test_apk_comparison.py" -v
```

Тесты сравнивают эталонный вывод `apk dot` и `apk info -R` с графом
`depgraph` и с выводом `stage2` на выгрузке индекса; интернет не нужен.
